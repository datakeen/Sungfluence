# SungFluence: developer guide

SungFluence turns images into art made of letters. It is open source under the GNU AGPL, version 3 or later. These notes explain how the code is laid out and the rules that keep the app good. They apply to everyone who works on the code.

The name is written **SungFluence** (capital F) wherever people read it: window title, About, installers, docs. Code names are different and must stay stable: the plugin API `Sungfluence.plugin` (`SungFluence.plugin` is an alias), the npm name `sungfluence`, the storage keys `sungfluence-*`, and the repository `datakeen/Sungfluence`. Some older storage keys and project files are still read for compatibility; keep that code.

## How the code is organized

- `app/` is the source. Edit only here.
- `scripts/build.js` builds `src/` from `app/`. Run `npm run build` after every change. `npm start` builds first.
- `src/` is generated and committed, so a double-click on `src/index.html` works. Never edit `src/app.js`, `src/engine.js`, `src/samples.js`, `src/plugin-files.js`, `src/help.js`, `src/help/`, `src/plugins/`, `src/index.html`, `src/styles.css` or `src/sw.js` by hand. `src/fonts`, `src/vendor`, `src/icons`, `src/pwa.js` and `src/manifest.webmanifest` are kept by hand.
- Help pages live in `docs/help/*.md`. The build turns them into `src/help.js` and copies `docs/help/img` to `src/help/img`. `docs/help/styles.md` and `shortcuts.md` are generated by `scripts/docs.js` from `01-data.js`, the plugins and `SHORTCUTS`: never edit them by hand. When a panel or a label changes, update the hand-written help page in the same commit. `npm run help:shots` retakes the tutorial pictures.
- `npm run build:single` also writes `single/sungfluence.html`, one self-contained file that works without the other files, handy for quick tests and sharing.

| --- | --- |
| `app/engine.js` | Image to typographic scene. Styles (modes), line tracing, color models, SVG and text export, plugin registry. No DOM except canvas. |

| `app/parts/03b-objects.js` | Shapes, text and images on the Photo or Vector layer; select, scale, rotate; step and repeat; object SVG |

| `app/parts/03d-snap.js` | Snapping (`snapAt`, `snapMove`), its hint and the grid on the overlay. Kinds and defaults in `SNAP_KINDS` and `prefs.snap` |

| `app/parts/05-plugins.js` | Plugin loading, plugin controls, the Plugins window |

| `app/parts/05c-commands.js` | `COMMANDS`: every action with its label, keys, enabled and checked state. Builds the menu bar in the page (web), sends the same menus to the desktop app (`syncMenus`), the command palette (Ctrl K) and `runShortcut`. Add new actions here, not as loose key handlers. |
| `app/parts/06-io.js` | Undo, autosave, projects, export, the optional AI helpers, shortcuts, boot |

All parts share one function scope (the build wraps them). Order matters only for code that runs at load time.

## Commands

```bash
npm install
npm run build             # app/ -> src/
npm start                 # build, then open the desktop app
npm run web               # serve src/ at http://localhost:8080
npx playwright install chromium   # once, for tests
npm test                  # regression, plugin, studio, effects, and command and snapping tests
node tests/make-images.js # redraws the two test images in tests/images
npm run test:smoke        # opens src/index.html from disk, like a double-click
npm run dist:win          # or dist:linux, dist:mac
```

Tests write screenshots to `tests/out/`. Look at them after visual changes. Tests read `tests/images/portrait.jpg` and `tests/images/drawing.png`; `tests/effects.test.js` also uses the sample cat, to judge the effects on a real face. `tests/browser.js` falls back to an installed Chrome or Edge when Playwright's Chromium cannot start, which happens on some locked-down computers and inside sandboxed shells.

## Layers

Three layers: Photo, Vector (`doc.lines`: lines and vector objects) and Text art. `doc.order` lists them top first. Each has `visible`, `opacity` and `blend`. The eyes are the truth; the Photo, Mix and Text buttons are presets that set the eyes (`setView`, `syncViewSeg`). Layer visibility is left out of undo history. Objects (`doc.objects`) use image pixels like lines; `layer: 'photo'` objects are drawn into `photoSrc()`, so text art reads them. Image object pixels live in `assets`, outside history.

## Text in Urdu and Arabic

Arabic script joins its letters, so styles must never draw it one letter at a time. `ARABIC`, `RTL`, `famFor` and `famScale` in the engine pick a font that has it (Nastaliq by default) and set whole words, right to left. Calligram, Text portrait and Spiral do this; `post()` moves any stray Arabic letter to the Nastaliq font. Fonts for it are preloaded with Urdu sample text in `06-io.js`, because `document.fonts.load` without text only loads the Latin part.

## Rules that keep the app good

- **No freezing.** Target: no main-thread task over about 200 ms on a mid-range laptop (Intel i5, 8th generation). Heavy work is a generator (`function*`) that yields progress. The app runs generators in 8 to 14 ms slices (`runJob` in `02-core.js`, `sliceThumbs` in `04-ui.js`). Never add a synchronous loop over a full-size image. Known exception: switching preview quality rebuilds the photo view in one step (about 0.3 s).
- **Proxy previews.** Previews render at a smaller scale (`scene.scale`), exports at full size. Pixel settings named `size`, `spacing`, `minSize` and `maxSize` scale by themselves. A preview must look like its export.
- **One drawing list.** Every style returns items `{t: 'text' | 'rect', ...}`. Canvas, SVG, PDF, CMYK and text exports all read the same list.
- **Plugin API is public.** Do not change `Sungfluence.plugin` or the `api` object in `docs/PLUGINS.md` without raising `PLUGIN_API` and keeping old plugins working.
- **Offline desktop.** No CDN or Google Fonts calls from `src/`. The Content Security Policy in `src/index.html` allows scripts from the app folder and `blob:` (for user plugins) only.
- **Optional AI helpers** ("Direct" and "Suggest") use `window.claude`, which exists only when the page runs inside claude.ai. They hide themselves everywhere else. Keep it that way.
- **Privacy.** Photos never leave the computer. No analytics without an explicit opt-in. Anything that would send data off the computer is opt-in, uses the user's own key, and never stores keys in project files. Never put personal email addresses in files.
- **Writing in the UI and docs.** Short sentences. Plain US English. No em dashes. No hype. Every file in the repository speaks to its readers: users, contributors or plugin authors.

## How new code should fit

The project is growing into a full design studio (see `ROADMAP.md`). New code should already fit that shape:

- An action belongs in one function that a menu, a shortcut, a button and a test can all call. Register it in `COMMANDS`; do not bury logic in a click handler.
- A new export goes through one function that takes the scene and options and returns a file.
- Do not add more code that assumes exactly three layers. Read layers through `doc.order` and `layerOf`.
- Text that may be Urdu, Arabic or Persian is placed by word, never by letter.
- Add user-visible changes to the Unreleased part of `CHANGELOG.md` in the same commit.

Before a large change, propose a short plan and wait for the maintainer's go-ahead.

## Releases

See `docs/RELEASING.md`. In short: move the Unreleased changelog items under the new version, raise `version` in `package.json`, build, run all tests, check the screenshots, then push a `vX.Y.Z` tag. Keep SPDX lines in new files; the plugin template stays MIT on purpose.
